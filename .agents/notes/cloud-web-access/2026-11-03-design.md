# Cloud Web Access: narrow the MVP around existing Web/Server

The latest user goal is headless cloud ZCode accessed through Cloudflare with one deployment account/password. This changes the primary host from Electron desktop to the existing `zcode --web` server.

Verified current source before choosing a transport: ordinary `/ws` already creates independent replayable terminal scopes; Web bootstrap uses same-origin HTTP and WS. `packages/zcode-server-cli` Source Server is distinct from the Web HTTP server.

Recommend reusing the existing Web runtime with a password Worker gateway and Cloudflare Tunnel as outbound transport. A custom Worker/DO connector would also need HTTP streaming, WS multiplexing, cancellation and reconnect. Because Tunnel is an additional deployment component not previously chosen, document both and obtain the user's architectural decision before implementation, as required by AGENTS.md and the repository brainstorming workflow.

No remote resources, credentials, app state or source were changed. This commit contains reviewable planning documents only. Preserve deferred offline-reading, multi-instance dashboard and backup scope rather than silently claiming these in the MVP.
