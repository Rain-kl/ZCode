# Cloud Web Access scope revision, 2026-11-03

The user explicitly narrowed this release to the corresponding Cloudflare Relay, a headless ZCode Server connector, and the public `zcode server` command group: connect (TUI or arguments), up (foreground logs, -d background), down, and logs (-f follow).

Preserve official V2 single-owner replacement and mobile offline/error/cache behavior. Remove the draft many-to-many routing envelope, flow-credit messages, IndexedDB/offline-read feature and phased promises to ship these. Multiple independent SID pairs remain the existing device-directory semantics.

Reuse the current Source Server Supervisor, canonical server root, lifecycle locks, control endpoint, Core services and task runtime. Existing serve/stop/proxy-stdio calls must remain compatible with Desktop remote deployment. Packaging/launcher dispatch and persistent lifecycle logging are explicit work items; neither is assumed already complete.

connect configures only; foreground up owns its started service and graceful shutdown; down stops the whole Server and waits; logs never starts the Server and interrupting logs does not stop it. Credentials are masked/received via stdin and redacted before logging. Relay readiness is auth_ack waiting/matched, not the presence of a phone.

This revision changes planning documents only in codex/cloud-web-access. Runtime, credentials, cloud resources and unrelated parallel changes in the original worktree are untouched. All acceptance cases remain planned.
