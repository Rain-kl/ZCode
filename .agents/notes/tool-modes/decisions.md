# tool-modes 决策记录（档位选择改为卡片）

日期：2026-09-30
关联：`docs/features/tool-modes/design.md`、`docs/features/tool-modes/implementation.md`、`FEATURES.md` 的
`tool-modes` 条目。内核、宿主服务与栏目的首版决策见上述两份文档（第一版 2026-09-29）。

## 1. 起因

首版把三档做成设置页的一个下拉框。用户看过实际界面后不接受：档位之间是**包含关系**
（标准 ⊃ 基础 ⊃ 极简），选择这件事需要「同屏比较每档换来什么」，而下拉框一次只显示当前一项，
比较时必须点开两次、还要记住上一次看到的内容。要求改成三张并列的大卡片，点卡片即启用。

## 2. 关键决策

### 2.1 卡片并列，不套组卡

- **决策**：三张卡片放在 `grid sm:grid-cols-3` 里裸排，外面不再包 `SettingsGroupCard`。
- **理由**：组卡是「设置行」的容器，行与行之间靠 `border-t` 分隔；卡片是并列的可选项，
  两者语法不同。把卡片塞进组卡会形成两层卡面，选中态的底色与组卡底色再也分不清层级
  （见 `DESIGN.md` 的 Cards and Panels）。总开关仍留在组卡里——它是单行的开关，本来就属于行语法。

### 2.2 选中信号靠描边与对勾，不靠底色

- **决策**：选中态复用仓库既有的可选中卡片语言（`border-foreground/60` + `bg-card-selected`
  - 实心小圆点对勾），但不假设底色一定可见。
- **理由**：实测浅色主题下 `--color-card-selected` 与 `--color-card` 都是白色，
  底色不提供任何区分度。运行时确认（CDP 读 `getComputedStyle`）选中与未选中的唯一差别是描边
  与对勾。这条实测写进了实现文档 §4，免得后续改配色的人把这两样当装饰去掉。

### 2.3 卡片正文写分组名，不写工具名

- **决策**：卡片正文是「文件读写、代码搜索、命令执行、联网访问」这类**分组概述**，
  并且不再展示任何逐工具清单或工具计数。
- **理由**：工具名的权威来源是 core 的注册表分类，渲染层 import 不到（跨包会把工具名变成第二份
  真相，上游改名即静默漂移）。首版还留着「工具计数」「后果说明」这类文案，实际只能由渲染层手写，
  等于把同一件事写两遍。分组名是产品语言，与分类同源但不同物，改分类时人要看一眼——这条代价
  写进了实现文档 §5.2。
- **反向测试**：`packages/ui/test/forkToolGroupsSection.test.ts` 断言的正是「正文里不得出现
  驼峰/下划线标识符」，防止日后有人把工具名粘进 locale。

### 2.4 档位全集上提到契约，消掉一处镜像

- **决策**：`@zcode/shared` 新增运行时数组 `FORK_TOOL_MODES`，`isForkToolMode` 与界面卡片列表
  都读它。
- **理由**：卡片列表本来要在渲染层再抄一份 `["minimal","basic","standard"]`——契约里已有同一个
  联合类型的字面量判定，这就是一份必然漂移的镜像。上提成数组后，卡片顺序 = 数组顺序（能力递增）
  成为契约的一部分，增删档位只改一处；判定函数的实现也从三个 `===` 变成读同一个数组，
  「加了档位忘了改判定」被 `packages/shared/test/forkToolModes.test.ts` 的断言挡住。

### 2.5 关闭「注入工具」时整档禁用，而不是隐藏

- **决策**：总开关关闭时三张卡片 `disabled`（保留可见，opacity 0.6），脚注由「对新会话生效」
  换成「已关闭工具注入，档位不生效」。
- **理由**：此时 `toolAllowlist` 就是空数组，档位不参与解析。隐藏卡片会让用户以为档位没了、
  重新打开总开关时又要重新找；可点却什么都不改变则是更坏的设计。保留 + 禁用 + 说明，
  用户一眼知道「档位还在，只是现在不生效」。

## 3. 验证

运行中的 dev 实例（Vite HMR + CDP 9229）实测：三卡片按极简→基础→标准排列、标准档带选中标记；
点「极简」后标记移动且 `tool-groups.json` 落盘 `mode: "minimal"`；关总开关后三张卡片 `disabled`
且脚注切换。验证后把状态文件还原为验证前的字节。暗色主题未验证（要改用户当前主题）。
